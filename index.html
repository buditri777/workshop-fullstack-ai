11 · STEP 1 · PRD

Bikin PRD Dulu, Coding Belakangan 📝

PRD = Product Requirements Document. Ini blueprint sebelum AI nulis satu baris kode pun. Tanpa PRD, hasil AI generic dan ngaco.

💬 Prompt ke AI Agent (copy-paste ini)
Saya mau bikin Task Manager Web App.
Sebelum kita coding, tolong bikinkan saya PRD lengkap dengan format:

1. Overview
   - Apa masalah yang dipecahkan
   - Siapa target user
   - Value proposition utama

2. User Stories
   - Format: "Sebagai [user], saya bisa [aksi] supaya [tujuan]"
   - Cover semua fitur utama

3. Fitur Utama
   - List fitur dengan priority (must-have / nice-to-have)
   - Penjelasan singkat tiap fitur

4. Database Schema
   - Tabel apa aja
   - Kolom + tipe data + relasi
   - Aturan akses (siapa bisa lihat apa)

5. User Flow
   - Step by step dari user buka app sampai pakai fitur
   - Edge case (lupa password, data kosong, error)

6. Tech Stack
   - Pilih yang paling cocok untuk free tier
   - Jelaskan alasan tiap pilihan

Tanya saya kalau ada yang ambigu sebelum mulai nulis.
💡 Pro tip: Simpan output AI ke file PRD.md di project. Tiap kali AI agak ngaco, tinggal bilang: "baca PRD.md dulu sebelum lanjut".

13 · PROMPT

Framework PROMPT yang Baik

P

Persona

"Kamu adalah senior fullstack developer dengan expertise Next.js + Supabase..."

R

Requirement

Spec lengkap: tech stack, fitur, constraint, target user. Atau tunjuk ke PRD.md.

O

Output Format

"Jelaskan rencana dulu, baru execute. Setelah selesai, kasih ringkasan + langkah test."

M

Mode

Step-by-step, tanya kalau ambigu, jangan asumsi. Pakai skill yang sudah keinstall.

P

Pitfalls

"Hindari hardcode credentials, jangan skip RLS, mobile-first design."

T

Test & Commit

"Setelah selesai dan jalan, langsung git commit dengan message yang jelas."

15 · DATABASE

Setup Database via Prompt 🗄️

Kamu nggak nulis SQL. Kamu jelasin ke AI mau simpan data apa, AI yang generate semua.

💬 Prompt ke AI
Berdasar PRD.md, tolong setup database Supabase untuk app saya:

1. Generate SQL schema untuk semua tabel di PRD
2. Aktifin Row Level Security — user cuma bisa akses data miliknya
3. Bikin policy untuk select, insert, update, delete
4. Tambahin index buat kolom yang sering di-query
5. Generate seed data 5 contoh tasks untuk testing

Setelah selesai:
- Kasih saya step-by-step cara apply ke Supabase dashboard
- Test connection dari project Next.js
- Commit hasilnya: "feat(db): add tasks schema with RLS"
🤖 Yang AI Lakukan
✓ Baca PRD.md untuk dapat schema requirements
✓ Generate SQL lengkap di file supabase/schema.sql
✓ Generate RLS policies di supabase/policies.sql
✓ Generate seed data di supabase/seed.sql
✓ Tulis dokumentasi di docs/database-setup.md
✓ Setup Supabase client di lib/supabase.ts
✓ Test koneksi → all green
✓ Git commit: "feat(db): add tasks schema with RLS"
🎯 Kuncinya: kamu jelasin "apa", AI ngerjain "bagaimana". Tugas kamu cuma copy SQL ke Supabase dashboard sekali doang.

17 · GIT DISCIPLINE

Disiplin: Commit per Perubahan 🔁

Aturan paling penting: 1 fitur = 1 commit. AI yang ngerjain, kamu yang pastiin disiplin ini ditegakkan.

🛟

Bisa Roll Back

Kalau AI bikin yang ngaco, tinggal "balikin ke commit sebelumnya". Hidup terselamatkan.

🧠

AI Lebih Fokus

1 commit = 1 task. AI nggak pusing, kamu nggak pusing. Hasil lebih clean.

📜

History yang Bermakna

Lihat commit history = lihat journey product kamu. Recruiter suka.

⚡

Aturan Standing Order ke AI

"Setiap selesai 1 fitur kecil dan udah dipastikan jalan, langsung git commit dengan format conventional commits (feat / fix / docs / chore / refactor). Jangan tunggu saya minta."

📋

Contoh Commit Message yang Bagus

feat(auth): add register page · feat(tasks): add CRUD operations · fix(rls): correct policy for task update · docs: update README with setup steps

19 · SECURITY

Yang Wajib Tahu Soal Keamanan 🔐

AI bisa salah simpan credential. Kamu yang harus pastiin aman.

🗝️

API Keys ≠ Kode

Credential database / API key disimpan di file environment, bukan di kode. AI udah handle ini, tapi kamu wajib cek.

🚫

Jangan Pernah Commit .env

File .env tidak boleh masuk GitHub. AI biasanya auto-tambah ke .gitignore — kamu pastiin.

🔄

Kalau Bocor, Rotate

Kalau credential ke-push ke public repo, langsung ganti semua key di Supabase & Vercel.

⚠️ Prompt Wajib ke AI Sebelum Push

"Sebelum git push, audit project: pastikan .env di .gitignore, nggak ada API key di-hardcode, dan secret keys cuma dipakai di server-side. Kasih saya laporan."

✅ Hasil: AI scan semua file, kasih checklist hijau / merah, dan auto-fix kalau nemu issue.

22 · MISTAKES

Kesalahan yang Sering Terjadi ❌

🤖

Trust AI 100%

AI bisa hallucinate. Selalu verify: jalankan app, klik fiturnya, baca log. Jangan langsung commit blind.

📋

Skip PRD, Langsung Coding

Hasilnya generic dan ngaco. PRD = blueprint. Tanpa blueprint, rumah pasti miring.

🔑

Lupa Cek .gitignore

Token bocor ke GitHub publik = orang bisa akses database kamu. Selalu cek sebelum push.

💾

Coding 2 Jam Tanpa Commit

AI ngaco di tengah jalan? Selamat, kamu mulai dari nol. Disiplin commit per fitur.

🚫

Skip Row Level Security

Tanpa RLS di Supabase, user A bisa baca data user B. Wajib enable. Tanya AI: "audit RLS saya".

🎨

Default Tailwind Tanpa Polish

Bare default = obvious AI-generated. Kasih sentuhan personal: warna brand, illustration, font custom.
